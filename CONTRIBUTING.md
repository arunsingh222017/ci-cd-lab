# How we work

- Branch from main. Name branches feature/<short-description> or bugfix/<short-description>.
- Keep branches short-lived and pull requests small, with a single purpose.
- Write commit messages as an imperative summary of the change.
- Every change goes through a pull request. Nobody pushes to main directly.
- Reviewers aim to respond within one working day.
- We merge with squash and merge, and the branch is deleted afterwards.
- Never commit secrets. If one slips through, tell the team at once so it can be rotated.
